# 企业级 Agent 架构审查清单（上线前门禁）

> 用法：每次 agent 准备进生产前，逐项勾选。任一 🔴 项未过，**禁止上线**。
> 本清单对齐 Katory「Architecture Review Board 必问题」+ Artefact「non-negotiables」。

## 一、业务与范围
- [ ] 业务目标可量化（节省工时 / 降本 / 控险）？
- [ ] 是否已考虑「确定性工作流 / 简单 AI 辅助」而非 agent loop？
- [ ] 允许的作用域是否显式界定？
- [ ] 失败后果是否已知？
- [ ] 是否有具名业务 owner？

## 二、Agent 行为
- [ ] 模型决策 vs 确定性决策的边界是否文档化？
- [ ] 规划 / 重试 / 停止条件是否有界？
- [ ] agent 记忆是否必要、可控、可审查？（非默认全存）
- [ ] 多 agent 互动是否有据（上下文稀释 / 专业化 / 并行需求）？
- [ ] 失败后能否完整恢复任务状态？

## 三、数据与知识
- [ ] 权威数据源是否已识别？
- [ ] 检索前访问控制是否生效？
- [ ] 来源溯源是否保留（区分"检索事实"与"模型推理"）？
- [ ] 个人 / 机密 / 受监管数据是否妥善处理？
- [ ] 错误记忆或索引内容能否更正 / 删除？

## 四、身份与权限 🔴
- [ ] agent 是否有唯一工作负载身份？
- [ ] 发起用户 / 进程身份是否贯穿每次 tool call？
- [ ] 权限是否短时效、任务级（task-scoped, short-lived）？
- [ ] 事务 / 目的 / 资源限制是否强制？
- [ ] 权限能否立即撤销？
- [ ] 写入工具与读取工具是否分离？

## 五、工具与动作 🔴
- [ ] 每个工具是否注册、有 owner、有风险评级？
- [ ] 工具输入是否 schema 校验、输出是否按不可信处理？
- [ ] 写工具与读工具是否分离？
- [ ] 动作是否幂等或可回滚？
- [ ] 高影响动作是否独立审批（非模型自审）？

## 六、安全与韧性 🔴
- [ ] 是否对所有外部内容通道测过 prompt injection？
- [ ] 工具滥用 / 数据泄漏 / 供应链风险是否覆盖？
- [ ] 循环 / 级联失败 / 失控扇出是否有界？
- [ ] 熔断与紧急关停是否测过？
- [ ] 能否回退到安全的人工 / 确定性流程？

## 七、评测与运维 🔴（eval）
- [ ] 是否有代表性评测数据集？
- [ ] 质量 / 安全 / 成本 / 可靠性阈值是否定义？
- [ ] agent / 模型 / prompt / 工具 / 策略版本是否可追溯？
- [ ] 审计记录是否足以重建每次实质动作？
- [ ] 支持 / 事件响应 / 回滚责任是否分配？

## 八、治理与合规 🔴
- [ ] agent 是否登记进企业 AI 资产清单？
- [ ] 用例是否对照适用法律法规与政策评估？
- [ ] 人审安排是否有意义（按风险分级）？
- [ ] 留存与数据驻留控制是否满足？
- [ ] 多租户数据是否严格隔离（无跨租户共享）？

## 九、成本与可观测 🔴
- [ ] 是否有 per-run / per-tenant / per-user 预算硬上限？
- [ ] 是否有步数 / 超时 / token 上限（防失控循环）？
- [ ] 是否每步记录 trace（输入 / 输出 / 工具 / token / 延迟）？
- [ ] 成本与质量看板是否并排审阅？
- [ ] 反馈回路是否把生产失败转为新 eval case？
